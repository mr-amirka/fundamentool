# `EventEmitter` — базовый класс для класса с событийной моделью

[English version](./README.md)

Один из самых распространённых и ожидаемых паттернов, оставленный лёгкой абстракцией (fundamentool D-111): класс
наследует его и становится источником событий — генерирует их защищённым `emit`, его пользователи вызывают
`subscribe`. Оставляет выбор пользователям библиотеки и служит базой собственных источников событий лаборатории
(`RpcClient`, `RpcClientPool`: рассылки сервера).

## Когда нужен

- Класс, у экземпляров которого есть событийная модель: клиент, слышащий свой сервер, соединение, устройство, воркер.
- Тип для приёма: `IEventEmitter<T>` — всё, у чего есть `subscribe`, `clear`, `destroy`.

```ts
class Saver extends EventEmitter<string> {
  save(id: string) { /* … */ this.emit(id); }
}
const saver = new Saver();
const off = saver.subscribe((id) => console.log('saved', id));
saver.once((id) => console.log('the first save', id));
saver.save('note-7'); // выводит "saved note-7", затем "the first save note-7"
saver.save('note-8'); // выводит "saved note-8"
off();
saver.destroy();      // слушателей не осталось; последующий subscribe ничего не услышит
```

| Член | Что делает |
|------|------------|
| `subscribe(...listeners)` | добавляет их; возвращает одну функцию, удаляющую всех |
| `once(...listeners)` | как `subscribe`, удаляется после первого события |
| `protected emit(data)` | вызывает каждого слушателя; бросивший логируется, остальные выполняются |
| `clear()` | убирает всех слушателей; эмиттер продолжает жить |
| `destroy()` | убирает всех слушателей; последующий `subscribe` ничего не делает |

`emit` ничего не копирует (D-112): список заменяется при подписке и отписке; слушатель, добавленный во время `emit`,
услышит следующий, удалённый во время него — ещё услышит этот.
