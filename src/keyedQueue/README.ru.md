# keyedQueue — фоновая работа по ключу

[English version](./README.md)

Работа кладётся под ключ с приоритетом; один исполнитель берёт сначала высший, пачкой (fundamentool D-106). Тот же ключ,
положенный снова до запуска, остаётся одним элементом — с последним значением и высшим приоритетом.

## Когда нужен

- Работа приходит всплесками, и важно только последнее состояние: файл, сохранённый пять раз за секунду, индексируется
  один раз; узел, изменённый дважды, эмбеддится один раз — с последним текстом.
- Фоновая работа, где некоторые элементы должны пройти без очереди: только что отредактированное пользователем — раньше
  остального бэклога; одобренные решения — раньше прочего текста.
- Долгий фоновый прогон, который срочное должно прервать (`preempt`): прогон прерывается сигналом, его пачка
  возвращается, срочный элемент берётся первым.
- Один исполнитель за раз над общим ресурсом — базой, моделью — при работе, которую ставят многие (вотчер, хук, запрос).
- Фоновая задача, которая никогда не останавливает то, чему служит: упавший прогон сохраняется для показа (`error()`),
  очередь идёт дальше.

```ts
import { keyedQueue } from 'fundamentool';

const queue = keyedQueue<string, 'edited' | 'watched'>({
  run: async (batch, signal) => {          // сначала высший приоритет; signal прерывается при stop или вытеснении
    await reindex(batch.map((item) => item.key), signal);
  },
  batch: Infinity,                         // всё поставленное сразу (по умолчанию 1)
  preempt: true,                           // высший приоритет прерывает низший прогон; его пачка придёт снова
});

queue.put('docs/a.md', 'watched', 1);
queue.put('docs/a.md', 'edited', 2);      // один элемент: значение 'edited', приоритет 2
queue.put('*', 'watched', 0);             // после, если не придёт что-то выше
await queue.settled();                    // ничего в очереди, прогона нет
queue.error();                            // ошибка последнего упавшего прогона или undefined
await queue.stop();                       // очередь сброшена, прогон прерван и дождан
```

## Поведение

| Случай | Что происходит |
|--------|----------------|
| ключ положен снова, пока ждёт | один элемент: последнее значение, высший приоритет, место среди равных — первого положения |
| ключ положен, пока идёт его пачка | ставится снова, идёт после (исполнитель видел старое значение) |
| равные приоритеты | в порядке первого положения ключей |
| `preempt` и элемент выше низшего приоритета идущей пачки | сигнал прогона прерывается; когда прогон закончится, пачка возвращается под положенное с тех пор (новые значения побеждают) — исполнитель должен спокойно делать элемент повторно |
| прогон бросил (не остановлен, не вытеснен) | `onError(error, batch)`; его элементы сброшены (положите снова); `error()` хранит её, пока прогон не закончится успешно |
| `stop()` | очередь сброшена, прогон прерван и дождан, ошибка не сохраняется; `put` после — ничего не делает |

Не здесь, намеренно: сохранение на диск (очередь в памяти — её источник истины у вызывающего, перечитывается при
перезапуске), несколько исполнителей сразу (один владелец записей), повторы с задержкой (вызывающий кладёт снова — дверь:
`onError`, который это делает).
