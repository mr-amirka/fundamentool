# tupleLog — записи кортежами, формат с версиями

[English version](./README.md)

Журнал записей, по одной в строке, массивами JSON — сначала тип, затем поля по местам; имена полей хранятся один раз,
в схеме (fundamentool D-108). У формата есть версии: строка `["~", n]` говорит версию строк после неё, а каждая версия
переводит в себя записи предыдущей, поэтому файл только дописывается, а каждая строка читается в новейшей версии.

## Когда нужен

- Журнал, который только растёт и хранится навсегда, — чат, аудит, события, — где повторяющиеся имена полей объекта
  были бы большей частью его размера.
- Формат, который будет меняться, пока старые файлы остаются как есть: добавить поле, переименовать, убрать тип — старые
  строки читаются через новую версию, ничего не переписывается.
- Схема, которой может следовать читатель на другом языке: `schema()` — файл, который кладут рядом с журналами.
- Строки, которые могут быть сломаны или чужими: каждая — проблема с номером строки, остальные читаются.

Пример и таблица членов — в [английской версии](./README.md): `tupleLog({ name, versions })`, `head()`, `line(record)`,
`read(text)` → `{ records, problems, dropped }`, `schema()`. `up(record)` версии получает запись в именах предыдущей
версии и возвращает её в своих или `null` — тогда запись не берётся (`dropped`). Без `up` поля, которые версия
называет, переносятся по имени, новое — `null`, а тип, которого версия больше не называет, не берётся.
